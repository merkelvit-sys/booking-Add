# Инструкция по развёртыванию: годовой график + Google Sheets + автообновление

Этот проект связывает клиентское приложение (`index.html` / `index_ua.html` / `index_de.html`)
с Google Таблицами как с **Единым источником правды (Single Source of Truth)**.
При каждом запуске приложение показывает экран загрузки, фоново забирает свежий график
с Google Apps Script и перерисовывает интерфейс. При отсутствии сети — работает с кэшем офлайн.

---

## 1. Google Apps Script (сторона Google Таблиц)

### Куда вставить код
1. Откройте вашу Google Таблицу (ту, где хранятся записи на служение).
2. `Расширения` → `Apps Script` (или `Инструменты` → `Редактор скриптов`).
3. Удалите содержимое файла `Code.gs` и вставьте туда **весь код из `google_script.txt`**
   (этот файл уже готов к деплою).
4. Скрипт сам создаст вкладку **`YearSchedule`** при первом запросе и заполнит её
   всеми днями текущего года (статус по умолчанию — «Служение»).

### Как получить URL для подключения (важно!)
1. В редакторе Apps Script нажмите **«Развернуть» (Deploy)** → **«Новое развертывание» (New deployment)**.
2. В поле «Тип» выберите **«Веб-приложение» (Web app)**.
3. Настройте доступ **обязательно** так:
   - **Выполнять от имени:** `Я` (Execute as: **Me**)
   - **Кто имеет доступ:** `Все, даже анонимные` (Who has access: **Anyone**)
   > Иначе пользователи без вашей учётной записи не смогут дойти до таблицы, и приложение
   > у всех, кроме вас, будет падать с ошибкой доступа.
4. Нажмите «Развернуть», авторизуйте скрипт (нужны права на таблицы).
5. Скопируйте полученный **URL** вида:
   `https://script.google.com/macros/s/XXXXXXXXXXXXXXXX/exec`

### CORS / preflight
Скрипт уже отвечает на `OPTIONS` (preflight) корректными заголовками CORS
(`Access-Control-Allow-Origin: *`), а POST-запросы отправляются в режиме `no-cors`,
поэтому браузеры пользователей не блокируют отправку данных. Дополнительно настраивать ничего не нужно.

## 2. Подключение клиента (вставить URL)

В файле `app.js` (общий для всех языковых версий) найдите строку:

```js
const GOOGLE_SCRIPT_URL = "https://script.google.com/macros/s/.../exec";
```

и замените её на **тот же самый** URL из шага 1.5. Этот URL используется во всех трёх
языковых версиях (`index.html` / `index_ua.html` / `index_de.html`), так как вся логика
клиента вынесена в общий `app.js`.

> Ключ доступа (`jw_144000`) уже прописан и в скрипте, и в `app-sync.js`.
> Если вы его меняете в `google_script.txt`, поменяйте его и в `app-sync.js`
> (константа `API_KEY`).

## 3. Что было реализовано

### Годовой график (Yearly Grid)
- Новая вкладка **«Год»** (RU) / **«Рік»** (UA) / **«Jahr»** (DE) с компактной сеткой
  на 12 месяцев (365/366 дней). Каждый день — карточка с уникальным ID `YYYY-MM-DD`,
  цветовым статусом, подсветкой «сегодня» и прошедших дней.
- Рендеринг через `DocumentFragment` — интерфейс не зависает даже на 366 ячейках.
- Клик по дню открывает редактор: **статус** (`Служение / Выходной / Событие / Праздник / Особое`),
  **описание события** и **заметка**. Изменения валидируются и мгновенно сохраняются локально
  и отправляются в Google Таблицы.

### Интеграция с Google Sheets (GAS)
- `doGet` возвращает **объединённый** JSON: `{ status, bookings, schedule }` — один запрос
  вместо нескольких (минимизация обращений к API).
- `doPost` обрабатывает записи на служение (`create` / `delete`) и обновление дня графика
  (`action=year_update`).
- Вкладка `YearSchedule` — единый источник правды для годового расписания.

### Автообновление при запуске
1. При старте показывается **splash-экран** (экран загрузки).
2. В фоне `SyncCore.runAppLaunch()` делает один GET-запрос к Google Apps Script.
3. При успехе: локальные данные (`databaseBookings` + кэш графика в `localStorage`)
   перезаписываются, интерфейс перерисовывается, splash скрывается.
4. При ошибке сети: загружается последний кэш (`localStorage`), график открывается в
   **офлайн-режиме**, пользователь уведомляется тоастом.
5. Фоновая синхронизация продолжается каждые **60 сек** (только когда вкладка активна)
   и при возврате на вкладку (`visibilitychange`).

### Безопасность и оптимизация
- Один GET на старте + редкие фоновые обновления (60 с, пауза в фоне).
- Клиентская валидация даты/статуса/длины полей перед отправкой (`validateDay`).
- Серверная валидация дублируется в GAS.
- Ключ доступа проверяется на каждом запросе.

## 5. Проверка

1. Откройте `index.html` в браузере (или задеплойте как PWA).
2. Вы должны увидеть splash-экран, затем вкладку «Запись».
3. Перейдите на вкладку **«Год»** — появится годовая сетка.
4. Кликните любой день → выберите статус/описание → «Сохранить».
5. Откройте вкладку `YearSchedule` в Google Таблице — изменения появятся там.
6. Обновите страницу (Ctrl+R) — график подтянется с таблицы автоматически.
7. Отключите интернет и обновите — приложение откроется из кэша с пометкой «Офлайн».

## 6. Если запись в годовом графике «не сохраняется»

Самая частая причина: **Web App всё ещё отдаёт СТАРЫЙ код скрипта.** Просто сохранить
`google_script.txt` в редакторе недостаточно — Google выдаёт код только из последнего
**развёртывания (deployment)**.

Признак в приложении: после сохранения дня появляется красное уведомление
«Сервер не сохранил изменения. Пересоздайте Web App (Deploy → New version)…».

Что сделать:
1. В редакторе Apps Script откройте `google_script.txt` (убедитесь, что там НОВЫЙ код
   с `doGet`/`handleYearUpdate`/`YearSchedule`).
2. «Развернуть» (Deploy) → «Управление развертываниями» (Manage deployments) →
   карандаш → **«Новая версия» (New version)** → Сохранить.
   (URL остаётся прежним, но начинает отдавать новый код.)
3. Перезагрузите приложение (Ctrl+R) и снова попробуйте сохранить день во вкладке «Год».
4. Убедитесь, что в таблице появилась вкладка **`YearSchedule`** и в ней меняется строка
   за выбранную дату.

Если вместо этого прилетает ошибка вида «Доступ запрещен» — проверьте, что в настройках
развёртывания стоит «Who has access: Anyone» (анонимные).
